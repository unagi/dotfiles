# Codexエージェントのモデル選定基準

モデルや担当の組み合わせを見直すメンテナ向けの判断基準。現行設定と判断履歴は[選択記録](codex-agent-model-selection.md)、変更の手順と検証は[モデル更新手順](instruction-maintenance.md#codexのモデル更新手順)に置く。

## 担当に残る仕事を見る

| 仕事 | 確認する点 |
| --- | --- |
| 意図を読み、問題を定める | 原文と推測を区別できるか。会話や資料から目的・制約・完了条件を捉え、判断を変える不明点を見つけられるか。 |
| 仮説を立て、方針を判断する | 重要な仮説を根拠や反証と照合し、現実的な選択肢と推奨を示せるか。人の判断が必要な場合も、何を選ぶのか、現時点でどの案が有力かを示せるか。 |
| 具体的な課題を実行する | 指定された成果、範囲、裁量、承認を守り、検証まで進められるか。障害や未完了を説明できるか。 |

同じ案件でも、考えるべき問題を見つける仕事と、具体化された課題を完遂する仕事は要求が異なる。担当に残る判断を見て、モデル・effort・役割・委任指示の組み合わせを評価する。個別テストや総合スコアから別の役割での優位を推定するときは、評価範囲と前提を示す。選べるeffortと実用上の価値を区別し、高effortによる能力向上を線形と仮定しない。

## 完了までの負担で比べる

- 人に求める判断や追指示、委任の準備・確認・再依頼、成果の修正、待ち時間、実際の消費を含める。回答が短くても、安全に進められる仕事を人へ戻す、あるいは材料のない選択を求めるなら、その負担を数える。重大な判断に必要な質問は内容とタイミングで評価する。
- 候補を比較するときは、役割に必要な権限・ツールと成果条件を揃える。同じモデルで指示の具体性を変える比較と、同じ指示でモデルを変える比較を区別する。指示言語を調べる場合も、原文の引用・構造・意味を保って指示本文の言語だけを変える。評価指標には意図の保持、案の判断しやすさ、成果の充足、手戻りを使う。
- 日常の具体例と負担感は見直しの材料になる。全件の採点や比較試験を採用・維持の前提にしない。API単価、Codexの利用枠、実測の総費用はそれぞれ扱い、未取得の数値を推定で埋めない。

## 根拠の種類を記録する

- **公式の仕様・説明**。提供条件、対応する機能、推奨用途を確認する。製品側の推奨は選定材料の一つとして扱う。
- **公開評価**。対象モデル、effort、課題、実行環境、採点方法を確認する。評価の対象外にある意図理解や統合、実運用の負担は別途確認する。
- **利用者の観察**。何を依頼し、どこで判断や手戻りが生じたかを記録する。観察だけで発生頻度やモデル固有の原因は確定しない。
- **運用上の仮説**。期待する分担・指示の効果、成立条件、反証や再評価の契機を示す。未確認事項は実績と区別する。
