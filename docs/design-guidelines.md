# デザインガイドラインの位置づけ

正本は [Web・UI/UXデザイン](../.chezmoitemplates/agent/engineering/design.md)。Codex・Claudeの `common/design.md` へ直接includeして配布する。root・Parent・childの規約から該当行為前に読み、実装入口にも参照先を示す。デザインだけの相談・レビューに開発手順全体を読み込ませない。

一般の要求整理、承認、実装・テスト、担当編成、独立レビューの条件は既存規約が所有する。ここでは利用の流れ、重要案の比較、視覚表現、実画面の批評に限定する。モデル・effort・権限は変更しない。指示と回答は既存の共通インターフェースを使い、新しい報告様式を重ねない。

## 教材との対応と限界

2026-11-06に参照した教材を基に、ユーザー提示の6観点をAI向けに構成した。

- [MIT GR2: Designs](https://web.mit.edu/6.813/www/sp18/assignments/gr2-designs/)：具体的な利用場面、実質的に異なる案、学びやすさ・効率・安全性の比較。授業で指定される3案の提出は運用へ持ち込まず、重要な未決事項だけを比較する。
- [Amy J. Ko, Design Methods](https://faculty.washington.edu/ajko/books/design-methods/)：問題理解・定義、発想、プロトタイプ、インターフェース設計を扱う教材。今回の参照は教材の構成と位置づけの確認であり、全章の検証ではない。
- [Web Style Guide, Graphic Design](https://webstyleguide.com/8-graphic-design.html)：内容と視覚表現の関係、タイポグラフィ、色・コントラスト、配置、可変画面での一貫性。教材の美的立場を唯一の正解にせず、対象の目的とブランドに合わせる。

6観点への統合、比較の省略条件、AIレビューと返却への接続は本リポジトリの運用設計である。教材がAIでの品質向上を実証したとは扱わない。AIによる点検はユーザーテストやアクセシビリティ適合検証の代替ではない。

## 受入ケース

| ケース | 期待する動作 |
| --- | --- |
| 既存の目的と制約が十分 | 既知の目的を聞き直さず、該当する設計へ進む |
| 主要な導線に重要な未決事項がある | 同じ利用場面で実質的に異なる案を比較し、採用理由と限界を示す |
| 文言・余白の小さな修正 | 多案比較や追加Reviewerを一律に要求せず、関連画面・状態を確認する |
| 操作できるが外観が狙いと合わない | 使いやすさと外観を分けて評価し、構成・文字・余白等の根拠を示す |
| 静止画だけを確認できる | 外観・表示の評価範囲を示し、操作や復帰経路は未検証とする |
| 描画や画面読解ができない | 外観確認済みとせず、必要な手段・資料と影響を返す |
| Reviewerがデザインを評価する | 原依頼と対象版を基に場所・問題・影響・修正方向・確認方法を返す。制作を代行しない |
| 狭い画面・エラー状態で修正の影響がある | 該当条件で再確認し、未確認の幅・状態・利用者評価を明示する |

上記は静的照合用であり、実モデルの遵守・品質改善を測定した結果ではない。
