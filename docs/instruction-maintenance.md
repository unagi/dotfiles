# 指示文書の保守ルール

## 対象と位置づけ

本書は、このリポジトリの指示・テンプレート・説明資料を編集するメンテナ向けの正本である。通常業務を行うエージェントへの行動指示ではなく、配布・includeの対象にしない。配布先の変更やchezmoi実行の許可も与えない。

本書は文書の責務と配置を定める。業務上の権限・承認・行動原則は対応する運用文書が定める。既存文書がこの構造に適合済みであることを意味せず、整理時も合意済みの意味・例外・承認条件を保持する。

## 文書ごとの責務

| 文書・配置 | 読者と読む場面 | 所有する内容 | 他へ置く内容 |
| --- | --- | --- | --- |
| リポジトリ直下の `AGENTS.md` | このリポジトリの作業担当 | source編集・検証・配布の境界、保守ルールへの入口 | 配布先での業務手順、保守ルール全文 |
| `dot_codex/AGENTS.md.tmpl`、`private_dot_claude/CLAUDE.md` | 各環境の通常エージェント | 常時必要な原則と制約、詳細指示を読む契機・参照先 | 階層別の詳細フロー、編成一覧、変更経緯 |
| `.chezmoitemplates/agent/common-rules/`、`common/` | 複数環境で同じ規則を使う担当 | 実際に共有する安全・開発等の規則の本文 | Codex固有の階層・ロール規則 |
| `dot_codex/common/root-agent.md.tmpl` | 起点が依頼全体の担当を決める前 | 自処理の外部指定範囲、対応順序、原文の受け渡し、兼務への移行条件 | childの作業手順、モデル設定、文書保守手順 |
| `dot_codex/common/sub-agent.md.tmpl` | 委任する担当 | 起動権限、履歴転送、再利用、記録の境界 | 起点の対話フロー全文、専門判断の方法 |
| `.chezmoitemplates/agent/codex/hypothesis.md` | Codexの全ロール | 仮説・提案の検討に共通する判断原則 | 相談先の選択・起動手順、役割別の報告書式 |
| 同ディレクトリの `parent.md` | parent・明示された兼務担当 | 案件責任、指示に対するchild受入、独立レビューの手配・判定管理、報告 | 職能固有の手順、起動権限の一覧 |
| 同ディレクトリの `child.md` | worker・Advisor・Reviewer・assistant | 末端担当の作業範囲、返却・記録、再委任禁止 | 案件全体の統合、起点の対応順序 |
| 同ディレクトリの `worker.md` | worker | 指示範囲内の局所判断・実行・検証 | ユーザー意図の再定義、案件全体の受入 |
| 同ディレクトリの `advisor.md` | Advisor | 方針相談・成立条件・改善案 | 独立レビュー、ユーザー承認 |
| 同ディレクトリの `reviewer.md` | Reviewer | 原依頼・解釈・成果の整合、ユーザーへ返せるかの判定 | childの工程管理、成果の作成 |
| `agent/roles/`、`agent/languages/` | Claude職能担当・該当言語の担当 | 対象環境・言語に固有の判断と検証 | Codexの職能ロールの復活 |
| `dot_codex/agents/*.toml.tmpl` | 起動側と該当ロール | モデル・effort等の設定、固有の目的・入出力・制約、共通本文の取り込み | 取り込む共通本文の言い換え、起点に対する長い行動指示 |
| `docs/codex-subagents.md` | 構造を知りたい利用者 | 全体像、情報の流れ、設計意図、正本へのリンク | 運用規則の独自追加、詳細手順の複製 |
| `docs/codex-agent-model-selection.md` | 編成を確認・評価する利用者とメンテナ | 設定由来の比較表、評価・受入ケース、変更経緯 | 設定や権限の別の正本 |
| 本書 | 指示を追加・変更・整理するメンテナ | 配置、重複、参照、変更・検証の基準 | 通常業務で読むべき行動規則 |
| `README.md` | リポジトリ利用者 | 目的、構造、各資料への入口 | 上記各文書の詳細な再掲 |

表のCodex専用文書を、Claude側へ自動的に一般化しない。既存の共有本文を変更するときは、include元を検索して双方への影響を確認する。新しい種類の文書が必要なら、読者・読む契機・所有内容・参照元を先にこの表へ定める。

## 配置を決める順序

1. 追加する内容が「業務の行動規則」「ロール固有の手順・設定」「人向けの説明」「メンテナの編集規則」のどれかを決める。
2. 対象読者と、その情報が必要になる場面を特定する。全員に必要なら共通本文、特定ロールだけならその本文へ置く。
3. 同じ判断を既に定める正本を検索する。存在するならそこを修正し、別の場所に補足規則を積み上げない。
4. 新規文書に分けるのは、読者・読む契機・更新理由が独立し、参照経路を維持できる場合とする。文字数だけで細分化しない。

## 重複と参照の基準

- 一つの判断規則には一つの正本を置く。正本以外には、必要な短い要約と参照先だけを置き、条件・例外を独自に追加しない。
- includeによる同じ本文の配布は、手書きの重複とは区別する。各担当に必要な本文が届くことを優先するが、取り込み後に同じ説明を再記述しない。
- ロール本文は各TOMLテンプレートから直接includeする。Rootの明示兼務用にはroot-agentテンプレートがParent本文をincludeする。共通Markdown本文に評価されない入れ子のincludeを置かない。
- 参照だけで届くと仮定しない。通常業務の担当が保守用docsを読まなくても動けるよう、必要な指示は配布される本文に含めるか、実際に読める配布先と読む契機を指定する。
- sourceの相対リンクと配布先の参照を区別する。メンテナ向け資料ではsourceへリンクし、運用本文に配布されないdocsへの必須参照を作らない。
- ロール側には「この担当が何を受け取り、何を判断し、何を返すか」を書く。依頼側には「いつ誰へ何を渡し、結果をどう扱うか」を書く。同じ受け渡しを両側から説明しても、共通原則や相手の手順全文は繰り返さない。
- 人向けの図・比較表は正本の説明として再掲できる。正本へのリンクを付け、正本変更時に追従させる。受入ケースは規則の具体化であり、新たな権限や例外を追加する場所にしない。
- 入口文書には詳細へ進むための要点を残す。重要な制約を削って短くするのではなく、判断の分岐が増える箇所を適切な正本へ移す。

## 変更と確認の手順

1. 変更前に、変更する判断規則、その正本、include・参照元、影響するロールと説明資料を特定する。
2. 内容を変える変更と、意味を保つ移動・重複除去を区別し、承認範囲を確認する。整理を理由に未承認の権限変更を混ぜない。
3. 正本を更新し、依存する本文・説明・リンクを同じ変更で合わせる。切り出した本文への入口を確保してから旧記述を整理する。過去の説明を残す場合は履歴であると明示する。
4. sourceの検索・差分確認で、同じ規則の別表現、古い例外、参照切れ、共通本文の再説明が残っていないか確認する。文書単体だけでなく、対象ロールが受け取る本文全体で確認する。
5. 既存の構文・include検証に加え、通常経路・例外・未解決時の受け渡しを具体例で照合する。静的な照合と実際のモデル動作試験を区別する。chezmoi実行と実環境反映には別途明示指示が必要である。

完了時は、正本の配置、削減した重複、保持した条件・例外、検証と未検証範囲を報告する。構文検査が通っただけで読みやすさや行動の改善を実証済みとしない。

## 運用上の確認

本書の追加だけで既存文書の整理完了とはしない。整理ごとに対象・保持条件・検証結果を確認する。Parent定義は `parent.md`、末端定義は `child.md` と担当別本文、全ロール定義は共通原則を明示的に取り込む。保守用docsを運用時の必須参照にしない。

## モデル・effortの決定根拠を残す

- 設定の正本は各TOML。現段階の解釈・根拠・変遷は [モデル選択資料](codex-agent-model-selection.md) に集約し、運用本文へ調査経緯を持ち込まない。
- 定義上選べるeffortと、担当業務で実用上選ぶ価値のあるeffortを区別する。高effortによる能力向上を線形と仮定しない。
- 見直しごとに日付、旧設定、新設定、対象の呼出元・仕事、採用理由、反証・限界、未確認事項を残す。過去の結論を根拠ごと消さず、変更履歴として要約する。
- 根拠を公式仕様・公開ベンチマーク・フォーラムの経験談・利用者の観測・運用上の判断に分ける。出典URL、確認日、比較条件を残し、確認できなかったことを測定事実にしない。
- 価格はAPI単価、Codexの利用枠、実測の総費用を区別する。初回の速度・単価だけでなく、指示・受入・再作業まで含めて評価する。
- 設定を変える際は呼出元とReviewerとの関係、プロンプトの適合、受入ケース、説明資料とCIを同時に確認する。未検証の候補は暫定と明示する。
