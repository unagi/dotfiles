# Codexサブエージェントの設計コンセプト

## 位置づけ

2026-09-14の設計整理。以下のコンセプトはエージェント向けsourceテンプレートへ反映済み。実環境への配布・起点のモデル設定は未実施。実行時は配布された指示と提示ツール仕様に従う。[現行の編成とモデル設定](codex-agent-model-selection.md)とは区別する。

## 一貫した案件を継続して任せる

意味の一貫した大きな案件は、同じメインスレッドで継続する。4時間の案件を10分24本のユーザー依頼へ分割して成功率を上げることは目標にしない。内部で1時間4本の担当へ分けても、目的・共通制約・相互の依存関係は同じ起点が保持する。

全体との結びつきが強く、重い仕事こそparentへ渡す。起点には関係性と主要な決定を残し、詳細な調査・試行・中間情報はparent内に閉じる。コンパクションをなくすのでなく、メインでの反復を減らし、その影響を担当範囲へ限定する。

## 役割と処理の選択

| 役割 | 責任 |
| --- | --- |
| 起点 | 依頼形成の補助、全体の目的・制約、担当選択、依存関係、全体調整、成果の統合 |
| Lunaアシスタント | 条件が明確なファイル要約、検索、抽出、変換など。根拠の所在と不確実性を添えて返し、採否は起点に残す |
| parent | まとまった担当範囲の方針、詳細調査、実装・検証、局所的なユーザー確認、成果責任 |
| child / advisor | parentが委任した限定範囲の遂行、必要時の助言 |

起点自身がchildを使う場合も含め、直接完遂するのは、そのコストがparentへの依頼・回収のオーバーヘッド未満の場合だけ。時間、トークン、起点に残る文脈、指示・回収・確認を含めて比較する。「中度案件は自身＋child」という基本経路は設けない。実際の直接処理は、その場で終わる回答・整形・全体管理が中心となる。

大量でも処理条件が明確ならアシスタント、まとまった判断と実作業ならparentへ渡す。依頼が長く回答が短いだけでは軽微と判定しない。アシスタントは起点直轄の固定的な役割とするが、同一個体の常時待機・永続利用は必須にしない。関連処理は再利用し、独立した処理は必要に応じて並列化する。待機していても指示・受信・確認のコストは残る。

## 起点のモデル

Lunaを起点の既定とする前提を改め、Terra/highを第一試行候補とする。大量読解と重い実作業を委任し、起点は依頼の理解と全体調整へ能力を使う。Terraで長時間の案件保持・依頼構成・IF解釈が十分かは未実測であり、複雑な制約調整や誤選択・手戻りが続く場合はSolと比較する。起点はhighから試し、判断不足が残ればxhighまたはSolと比較する。maxへの一律引き上げはしない。

[公式Subagentsのモデル選択](https://learn.chatgpt.com/docs/agent-configuration/subagents)はLunaを明確で限定的な処理、Terraを速度・効率を重視する処理に位置づけている。Terraをこの起点の第一候補にするのは本運用の仮説であり、公式による長時間調整能力の保証ではない。評価は起点単体の消費ではなく、総消費・手戻り・ユーザー介入・完了時間で行う。

### effortの調査根拠（2026-09-14）

[公式Terra仕様](https://developers.openai.com/api/docs/models/gpt-5.6-terra)のAPI既定はmediumだが、本用途の最適値を示すものではない。[個人の比較測定](https://github.com/ruyari-cupcake/terra-luna-routing-benchmark)ではTerra high/xhigh/maxの総合スコアが83.08/83.02/83.12、推論トークンの公開値が2,527/4,511/12,060だった。high以降の一律引き上げを支持しない参考材料とする。2026-07-31の14課題で通常セルは1回、一部のみ反復しており、長時間の案件管理やCodex利用枠への一般化はできない。

[maxでも早期終了が残った利用者報告](https://www.reddit.com/r/OpenaiCodex/comments/1vdbwek/gpt56_terra_prematurely_ends_autonomous_backlog/)もあり、継続や通知の問題をeffortだけで直す前提にしない。評価は依頼訂正、ツール誤選択、早期終了、救援介入、完了までの総消費で行う。

## parentとの直接対話と報告

ユーザーはparentと直接会話できるUIを前提とし、起点を全対話の代理中継者にしない。parentは担当範囲の疑問を直接確認し、局所的な会話履歴を保持する。共通制約、他の担当の前提、案件全体のスコープに影響する変更は、終了を待たず起点へ共有する。ユーザーの承認範囲は委任で拡張しない。

起点は細かな中間報告を繰り返し要求しない。担当の継続状態の確認と、作業内容の説明要求を区別する。全体調整が必要な決定・阻害要因・完了結果を受け取る。ユーザーの局所的な判断は必要でも、担当を再起動・再説明するための頻繁な介入を前提にしない。

## 指示書・応答書・状態

| 記録 | 管理方法 |
| --- | --- |
| 指示書 | 起点が目的、成果、担当範囲、制約・承認、依存関係、未決事項、必要な原文・資料を記す。当初依頼の正本として原則固定 |
| 応答書 | parentが訂正・追加決定・承認を時系列で追記。何が何を上書きしたか、誰の判断かを残し、未確定提案と区別 |
| 作業状態 | 現在の段階、残作業、次の行動を復帰可能な形で圧縮。会話全文や試行ログを再掲しない |
| 終了報告 | parentが応答書を要約し、最終仕様、当初からの変更、成果・検証、未解決事項を起点へ返す |

spawnは起動の合図とし、指示書の所在と担当範囲を渡す。指示書は案件が具体化した段階で作り、委任直前に圧縮済みの長い会話から再構成することへの依存を減らす。誤った要約はファイル化だけでは直らない。履歴非継承の制約を全文転載で迂回しない。

起点の復帰情報には、全体目的、共通制約、担当識別子、指示書・応答書・成果物の所在、全体に影響する決定、未完了事項と次の対応を残す。応答書の全履歴は起点へ戻さない。保存先は起動時にワークスペースルート基準の相対パスで指定し、`instruction.md`・`response.md`・`state.md`を例とする。保持期間は案件側の規約に従う。案件文書そのものをdotfilesの配布資産にはしない。

## 消費と品質への効果・限界

- 高能力の起点が大量の資料を直接読む回数を減らし、明確な情報処理をLunaへ寄せる。
- 詳細な試行錯誤と局所対話をparent内に保持し、メインの累積文脈、再圧縮、再説明を減らす。
- 代理中継と細かな進捗照会の往復を減らす。
- 原指示と訂正経緯を参照可能にし、圧縮と再要約による意図の欠落を減らす。

ファイルをparentが読む入力コストや文書の管理コストは残る。総消費の削減は未実測であり、通知未配送・待機ツール誤選択など実行環境の不具合は別途扱う。文書だけで通知や継続実行を保証しない。

## sourceへの反映と制約

起点・委任共通規約、parent/child本文、専用ロールと説明文書を本設計へ更新した。`assistant-L` はLuna/low・read-onlyの試行設定で、変換結果は回答で返す。

案件記録は共通安全規約に従い、ワークスペースの `AGENTS.md` を起点に既存領域を確認し、なければGit除外を先に整えて作成する。保存先の相対パスと用途を `AGENTS.md` に記載し、Git除外済み・未追跡の領域内で案件別・parent別に分ける。端末グローバルの領域への保存や、別案件データの暗黙の受け渡しは禁止する。指示書は起点、応答書と担当状態はparentが所有する。read-onlyのparentは追記本文を作り、指定された記録担当が保存する。終了だけを理由に記録を削除しない。

直接のユーザー対話が提供されない環境では起点による仲介を例外として使い、二重質問しない。並走する有用な作業など、実行ツールの起動条件を満たせない場合は制約を報告し、架空の並走作業や別タスク起動で迂回しない。通知・圧縮後の復帰は共通の状態記録と提供された状態取得手段で照合するが、ランタイム障害を文書で解決したとは扱わない。

## 現行のエージェント定義の管理方針

- ロール本文の正本は `.chezmoitemplates/agent/roles/` に置く
- Claude 用エージェントは `private_dot_claude/agents/*.md.tmpl` で frontmatter の差分だけを持つ
- Codex 用エージェントは `dot_codex/agents/*.toml.tmpl` で TOML、モデル、表示名とCodex固有の職能定義を持つ
- Codex 専用の parent / worker / advisor 規約の正本は `.chezmoitemplates/agent/codex/` に置く。共有する Claude のロール本文は変更しない
- 起点専用規約は `dot_codex/common/root-agent.md.tmpl` に分離して条件付きで参照し、AGENTSや各ロールへincludeしない。起動者共通の階層・権限・照合は `sub-agent.md.tmpl` に置く
- Codex の 19 定義は、メイン→parent→worker/advisorとメイン→assistantを基本にする。新規の独立委任は自己完結した入力と `fork_turns: "none"` を基本とし、parent が判断・統合・検証に責任を持つ。worker は担当範囲を調査または実装から検証まで完遂し、advisor は必要時の Astra 顧問として扱う
- 金融分析はSolのparent、数値取得はLunaのData worker、決算・開示等の分析はResearch workerに分担する。[市場データ取得台帳](../dot_codex/common/market-data-sources.md.tmpl)をCodexの共通ガイドとして配布する
- モデル、推論量、階級表示、parent の選択は [Codexエージェントの全体ツリー・モデル選択](codex-agent-model-selection.md#全体ツリー) を参照する
- `config.toml` は chezmoi 管理外であるため、メインモデル、深さ、同時実行枠はこのリポジトリからは変更しない。source から削除した旧エージェント定義が適用先から自動削除されるとは限らないため、整理時は適用先を明示して確認する


## CIでのCodexエージェント検証

GitHub Actionsの `Validate Codex agent TOML` は、関連ファイルのpush・PRと手動実行時に、Ubuntu上でchezmoi 2.70.3とPython 3.12を使い、`dot_codex/agents/*.toml.tmpl` の展開結果を標準ライブラリの `tomllib` で構文検証します。共通テンプレートの変更も検査対象です。

ローカルのPython・uv導入は不要です。設定の適用やモデルの利用可否の検証は行いません。`.github/` はリポジトリ保守用としてchezmoiの配布対象から除外します。
