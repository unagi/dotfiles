# Codexサブエージェントの設計コンセプト

## 位置づけ

2026-09-17の運用整理。起点は定義数に含めず、現行sourceはサブエージェント19定義（parent 10、worker 7、advisor 1、assistant-L 1）を管理する。具体的なロール、モデル、テンプレート適用、起動権限、移行先は[現行の編成とモデル選択](codex-agent-model-selection.md)にまとめる。実環境への配布、旧定義の削除、実起動、CI、消費評価は文書の更新だけでは行われない。

## 案件の持たせ方

意味の一貫した案件は、同じ起点スレッドで継続する。起点は目的、共通制約、担当選択、依存関係、全体調整、成果の統合を保持し、詳細な調査・試行・中間情報は担当へ渡す。起点が後続の判断に必要な背景を継続参照する案件は起点が直接扱う。必要な背景を選別した指示書だけで業務が成立するなら、規模が小さくてもparentを優先し、同じSol/lowでも文脈を分離する価値を比較する。

委任準備との比較が先に立つのはごく短い処理に限る。規模と判断難度は別軸で評価し、軽微専用のLuna parentや推論強度違いのparentは追加しない。小量でも曖昧な前提、矛盾、難しい設計がある場合は対応するcomplex parentを選び、大量でも条件が明確ならLuna workerを中心に分担する。未知の範囲は限定的な下見で不確実性を減らし、判断をchildへ丸投げしない。

委任時の指示書には確定条件、主要原文、過去の訂正、却下理由、未決事項、対象範囲、権限、受入条件、返却形式を含める。応答書と状態には追加決定、検証、残作業を残し、会話のcompactionだけに依存して案件を再構成しない。

## 役割と現在の構成

| 役割 | 現行の責任 |
| --- | --- |
| 起点（Sol/low） | 全体の目的、制約、parent選択、依存関係、ユーザーとの全体調整、成果統合 |
| assistant-L（Luna/low） | 条件が明確なファイル要約、検索、抽出、変換。根拠と不確実性を返す。起点直轄で再委譲しない |
| parent | 担当範囲の方針、詳細調査、実装・検証、必要な局所確認、成果責任 |
| worker | parentまたは起点から渡された独立範囲を調査または実装から検証まで完遂する |
| advisor（Astra/medium） | 難所の独立分析・反証。助言の採否、実装、統合、ユーザー承認は代行しない |

起点が選べるparentは、`architect`、`finance-lead`、`implementation-lead-H`、`implementation-lead-complex`、`research-lead-H`、`research-lead-complex`、`advanced-research-lead`、`recovery-lead`、`review-lead-astra`、`research-lead`の10定義に限る。起点は7つのworker、`advisor`、`assistant-L`も直接起動できる。

Sol parentとAstra parentは7つのworkerと`advisor`を起動できる。Lを中心に複数の独立範囲へ分担し、Mは担当範囲の探索・判断に明確な採用理由がある場合に使い、量だけでは選ばない。H childが1件だけになる場合は原則として自処理と比較し、独立反証や別の難所の並行処理など具体的な効果がある場合だけ例外として使う。この条件はH childの複数起動を一律に禁止するものではなく、各担当の独立性と具体的な効果を依頼に残す。親から別parentは起動しない。

Terra parentは、単純広域調査を複数Lunaで進める`research-lead`だけである。起動できるchildは`research-worker-L`、変更禁止の調査に限る`implementation-worker-L`、条件確定済み数値取得の`market-data-worker-L`だけで、M、H、`advisor`、他のparent、assistantは起動しない。解消できない矛盾、方針変更が必要な難所、重要な未確認事項は根拠と試行結果を添えて起点へ返し、独立して続けられる調査は継続する。Luna parentは定義せず、起動しない。

parentは別のparentを配下に置かない。child、assistant、advisorは再委譲しない。childの種類は権限を拡張せず、調査のみ、レビューのみ、変更可などの権限は案件ごとに指定する。ユーザーの承認範囲も委任によって拡張しない。

## 規模・難度・背景の判断

### 第1段階：背景と文脈分離

| 背景の確認 | 方針 |
| --- | --- |
| 後続判断まで背景を継続参照する必要がある | 起点が直接扱う |
| 背景を選別した指示書だけで業務が成立する | 小規模でもparentを優先し、文脈分離の価値を取る |
| ごく短く、背景の継続参照も不要 | 起点またはparent自身で処理し、委任準備と比較する |

### 第2段階：難度と規模

規模と難度は別軸で起動前に評価し、下見や調査結果に応じて見直す。媒体名や件数だけで能力帯を決めず、調査対象、予測される読解量、探索の広がり、比較数、返却量、前提の曖昧さ、矛盾の有無を合わせて判断する。

| 難度 \\ 規模 | 小 | 中 | 大 |
| --- | --- | --- | --- |
| 単純調査 | Sol/low parent、または限定child | Sol/low parent＋必要なLuna。分担管理が主ならTerra/high | Terra/high parent＋複数Luna |
| 通常調査・実装 | `research-lead-H` / `implementation-lead-H`が比較・解釈・局所判断を担う | 同parentがL中心で独立範囲を分担 | 同parentがL中心で複数範囲を統合 |
| 難解 | `research-lead-complex` / `implementation-lead-complex` / `architect`が難所を保持 | 同complex parentがL中心、採用理由を明記したMを必要時に使用 | 同complex parentがL中心で分担し、判断を統合 |
| 高リスクレビュー・原因分析・案件救援 | `recovery-lead` / `review-lead-astra`が自処理 | Astra parentがL中心で分担し、必要時にadvisorへ相談 | Astra parentがL中心で分担し、独立反証やadvisorを必要時に使う |

小量でも第1段階で切り出せると判断した業務はparentを優先する。起点が起動前の判断難度に応じてlowまたはmediumの固定ロールを選び、lowでの失敗をmedium採用の前提にしない。Sol/high effortはmediumで不足する難所の比較候補であり、今回一般調査・実装用ロールは増設しない。childのHはSolというモデル帯を表し、effortと区別する。M/H childは局所範囲の必要能力で選び、量だけで引き上げない。H child単独の丸投げは原則避け、独立反証や別の難所の並行処理など具体的な効果がある場合に例外として扱う。

媒体ではなく、調査対象、予測される読解量、探索の広がり、比較数、返却量、判断難度でworkerを選ぶ。parentは各論点から結論、根拠箇所、重要原文、適用条件、矛盾、未確認事項を受け取り、全資料の再読を前提にしない。

## 対話、統合、記録

parentは担当範囲の疑問をユーザーへ直接確認し、起点を全対話の代理中継者にしない。共通制約、他担当の前提、全体スコープに影響する回答や変更だけを起点へ共有する。直接対話できない環境では、起点が同じ質問を二重発行しない範囲で仲介する。

parentはworkerの結果を単に集計せず、根拠、適用条件、矛盾、結合結果を評価する。解消できない矛盾や方針変更は、証拠と未解決点を残して起点へ返す。未実行の検証を成功扱いせず、受入と承認はユーザーの判断に残す。

指示書は起点、応答書と担当状態はparentが所有する。記録は各リポジトリのGit除外済み未追跡`.tmp/`を案件別・parent別に使い、配布資産にはしない。`config.toml`はchezmoi管理外であり、起点のSol/low運用、同時実行枠、深さはsourceから変更しない。

## 評価と検証の扱い

通常業務のSol/low化とレビュー・救援のAstra/low化は別々に評価する。設定変更だけで効率改善が実証されたとは扱わない。

編成は単体の出力だけでなく、チーム総消費、手戻り、ユーザー介入、完了時間で評価する。起点の利用観測と合意した試行方針に基づく構成であり、モデル間の品質・価格の優劣を主張するものではない。

今回の19定義について、include/replaceの静的解決とPython 3.14のTOML解析、10 parentのモデル・effortと適用関係、220個の表示候補、read-only条件、廃止ロール参照の除去を確認した。詳細は[検証の扱い](codex-agent-model-selection.md#検証の扱い)を参照。chezmoi・CI・更新ロールの実起動・性能比較は未実施。静的検査は実行時の指示遵守を保証せず、起動禁止のツール側強制も実装していない。

過去のモデル選択、worker統合、表示名変更、記録分離の経緯は[モデル選択文書の過去記録](codex-agent-model-selection.md#過去の検討と検証記録)に残す。
