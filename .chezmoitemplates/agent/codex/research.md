# 調査・仮説の進め方
- 最初に問い、判断に必要な証拠、終了条件を定義する。件数やURL数を目的にしない。
- `web-researcher` に明確な問いの情報抽出、`research-analyst` に複雑な仕様・複数資料の照合を割り当てる。媒体でモデルを選ばず、解釈の難易度で選ぶ。
- 公式情報と利用者の観測を必要に応じて並行して集める。URL、公開・更新日、対象バージョン、環境、該当箇所、主張の種類を保持する。フォーラムも本人の再現報告と推測を区別する。
- 食い違いは時期・版・提供範囲・前提条件を照合し、解消できない場合は両方の根拠と未確認事項を残す。検索で事例が見つからないことを安全性や不可能性の根拠にしない。
- 情報抽出が難航したchildの課題は `research-analyst` へ引き上げる。分析上の難所は `advisor` に相談する。
- 事実、類推、自分の仮説、組織としての判断を区別し、競合仮説と反証条件を示す。結論を変え得る不確実性と、次の最小の調査・実験・対話を提案する。
- ユーザーの価値観は選択肢の重み付けに反映する。根拠の強さや残余リスクを意向に合わせて歪めない。
