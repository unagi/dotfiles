# Sol/Astra parentの委任規約

本文は通常業務を含む全parentに適用する。ファイル名のadvancedは難度・effortの指定ではない。起動権限・独立作業と有用な並走作業の条件は `~/.codex/common/sub-agent.md` に従う。

## childの選択
- Researchは外部仕様・事例・比較・仮説の収集から分析・報告、Implementationはコード調査・局所設計・変更・検証・変更禁止のレビュー、Market Dataは条件確定済み数値の取得・正規化・品質確認を担う。工程名でなく前提知識と成果で選ぶ。
- 個別検証できる独立範囲をL帯中心に分担する。M帯は探索・判断・速度等の採用理由と範囲を示す。局所範囲で能力帯を選び、案件全体の難しさ・量だけでH帯へ上げない。独立単位がなければ自処理し、数合わせはしない。
- 1 URL・単一ファイル・reader/writer等の工程だけでは分割せず、関連資料を含む論点で切り出す。共有境界・依存が強い範囲は順次処理し、書き込みは独立した変更境界だけ並列化する。
- H帯を1件だけ起動する難所は原則自処理する。独立反証や別の難所の並走など具体的な効果がある場合だけ、理由・範囲を示して例外とする。自身のモデル名でこの原則を変えない。
- read-onlyの調査parentがImplementationへ依頼できるのは変更禁止の確認・実現性確認・反証・既存成果物の検証まで。変更や試作が必要なら仮説・目的・終了条件・承認要否を起点経由で提示し、承認後は実装parentへ引き継ぐ。childでread-onlyを迂回しない。

## advisorへの相談
- 専門的な難所はAstra `advisor` に限定相談し、自ら助言の採否・検証・統合を行う。独立反証にも利用できる。目的・組織制約・証拠・試行結果・未解決の問い・仮説の狙いと成立条件・懸念を渡し、分析と改善案を求める。
- 案件全体の丸投げ、儀礼的レビュー、同じ証拠・方法での反復相談、枠埋めは禁止。追加相談は重要な新証拠が得られた場合の1回まで。
- なお解けない場合やユーザーの価値観・優先順位・リスク受容・範囲変更の承認が必要な場合は、理由と選択肢をユーザーへ返す。advisorで承認を代行せず、通常起点に専門判断を戻さない。起点は必要時の伝達を担う。
