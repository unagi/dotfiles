# プロジェクト用指示ファイル整備ガイド

- 最終確認日: 2026-03-02
- 位置づけ: この文書は「ユーザーグローバル設定」から参照する共通ガイド

## 目的
- プロジェクト内で LLM を利用する際に、指示ファイル（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md` など）を一貫した方針で整備する。
- テンプレートを強制せず、プロジェクト特性に合わせた判断基準を提供する。

## 基本原則
1. プロジェクトローカルの既存指示ファイルを優先し、重複作成を避ける。
2. 複数LLM運用では `AGENTS.md` を中核にし、LLM固有ファイルは差分のみ記載する。
3. 単一LLM運用では当該LLM向けファイル中心でもよい。
4. 指示は短く保ち、詳細は分割ドキュメントへ委譲する。

## 作成/更新手順
1. 現状確認:
   - 既存の `AGENTS.md` / `CLAUDE.md` / `GEMINI.md` の有無
   - README/Makefile/CI の正本コマンド
2. 対象と役割の整理:
   - 対象LLM（Codex/Claude/Copilot/Gemini等）
   - 共有ルールとLLM固有ルールの分離方針
3. 最低限の記載項目:
   - 実行コマンド（install/dev/lint/test/build）
   - 境界線（Never Do）
   - 品質ゲート（DoD）
   - 更新契機（いつ見直すか）
4. 運用定着:
   - 失敗事例・手戻り事例を次回更新でルール化する。

## 推奨チェック
- 記載コマンドが実際に実行可能か（CLI存在・引数妥当性）を確認する。
- 必要なコマンドラインツールが不足している場合は、回避実装で進めず導入を依頼する。
- 機密情報・本番影響領域の境界線を明示する。
