## サンドボックス・権限エラーの扱い

### 大原則
- ネットワーク系コマンドが失敗したら、原則 **サンドボックス制限** と断定する
  - 理由1: 真の広域ネットワーク障害ならエージェント API 自体が応答せず、この会話が成立していない
  - 理由2: 特定サービス障害（GitHub / AWS 等）も、ユーザーが作業を依頼した時点で
    対象サービスは依頼者側で事前確認されているため、稼働している前提が置ける
- 「ネットワーク不調かもしれない」と曖昧化したリトライは禁止
- 同じコマンドの再試行・コマンドを微変形しての回避試行・別ツールでの迂回試行 はすべてしない

### サンドボックス起因として扱う典型シグナル
- `Operation not permitted` / `Permission denied` / `EPERM` / `EACCES`
- ネットワーク系コマンドの失敗（curl/wget/git fetch/git push/gh/npm i/pip/uv sync 等）
  - DNS 失敗・connection refused・timeout の文言を見ても「ネット障害」と読み替えない
- ワークスペース外（`$HOME` 直下、`/etc`、`/usr` 等）への書き込み拒否

### 対応フロー
1. リトライしない
2. exit code と stderr 全文を提示
3. 必要権限・該当コマンド・理由 をセットで示し、ユーザーに昇格（または手元実行）を依頼して **停止**
4. 例外として「ユーザーが事前確認していないと考えられる外部依存」（例: Context7 など外部 MCP）が
   応答しないと**確信できる**場合のみ、代替手段を提示して停止。確信が無ければ 3 に倒す
