# コード変更

- `common/change-control.md` の承認条件を守る。`common/development.md` と、製品別入口に示された対象言語のガイドを読む。既読不変なら再読不要。
- 依頼側の仕様・受入条件・検証対象に沿って実装し、判断を変える不足は依頼元へ戻す。
- 変更前は `common/investigation.md` に従い、変更の影響と未解決の疑問に必要な範囲を調査する。確認済みの設計・根拠を再利用する。
- 同じ原因の再発や局所対応の限界が見えたら設計上の原因を見直す。修正回数だけで再設計せず、局所workerは上位方針を変える必要があれば根拠と改善案を依頼元へ返す。
- テスト・lintの前は `common/tdd.md`・`common/lint.md` を読む。Git変更操作の前は `common/git.md` を読む。
