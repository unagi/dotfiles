# 変更前の承認条件

- 承認された目的・範囲内の実装、検証、保守は、その影響に応じて判断して進める。ファイル数、新規ファイル、リファクタ等の形式だけで追加承認を求めない。要求・受入条件の変更、範囲拡大、互換性やデータへの重大な影響が承認に含まれない場合は先に確認する。破壊的・不可逆な操作や明示された承認条件は守り、担当権限を広げない。
- テスト変更は合意要求と必要な検証を保つかで判断し、`common/tdd.md` の原則に従う。実装を通すために要求や検証を黙って弱めない。
- 明示依頼がなければ実装変更と検証まで。commit/push/PR・コメントの前は `common/git.md` の承認条件を読む。
