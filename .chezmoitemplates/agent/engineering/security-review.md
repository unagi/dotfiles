# セキュリティレビュー観点

認証・認可、入力処理、外部連携など、脆弱性の見落としコストが高い設計・実装をレビューする担当は、対象コード・設計と変更差分を確認した上で次の観点を点検する。

- 入力検証・サニタイズ（SQLインジェクション、XSS、コマンドインジェクションなど）
- 認証・認可の抜け漏れ
- 秘密情報の取り扱い（ログ出力、ハードコード、過剰な権限やスコープ）
- 外部依存・サプライチェーンリスク
- エラー処理による情報漏洩
- セッション・トークン管理

発見したリスクには根拠、想定される攻撃経路、重大度（Critical / High / Medium / Low・情報）と推奨対策を添える。問題を発見しなかった場合も確認した観点を示す。推測でリスクを誇張しない。
