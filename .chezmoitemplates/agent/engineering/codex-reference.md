## Codex固有の参照手順

### 技術情報の確認
- まずプロジェクトで使う実バージョンを確認し、Context7でその版の一次資料を照合してから、実装に関わるAPI・設定・CLIオプション・推奨構成を案内する。回答では前提にした版を明示する。
- メジャーアップデート、非推奨機能、破壊的変更など、古い手順が混ざりやすい話題は必ずContext7で確認する。

### ファイル操作の高速化
- テキスト検索は `rg`（なければ `grep -R`）、ファイル探索は `fdfind`（なければ `find`）、閲覧は `batcat`（なければ `cat`）を使う。
- 差分確認は `git status -sb` の後に `git diff` を使う。`delta` がなければ通常のdiffを使う。
- 絞り込みに迷ったら `fzf` を組み合わせる（例: `rg ... | fzf`、`fdfind ... | fzf`）。

### Web参照
- まずローカルの一次情報（`--help`、`man`、リポジトリ内README・Docs）を確認する。
- Webページを読む必要がある場合は `lynx -dump` を優先し、利用できなければ `w3m -dump` を使う。`curl` と `wget` は最終手段とする。
- 同じURLの取得は原則1回にし、取得した出力を再利用する。

### GitHub CLI
- `gh pr create` の本文は改行保持のため `--body-file` または `-F` を使い、エスケープした改行を `--body` に渡さない。
