# 指摘後の修正と再試行

- 指摘全体の範囲と具体性で判断する。本人の正誤認識・修正難度で分岐を変えない。範囲が不明なら確認し、説明だけで修復を終えない。
- 狭域で改善点が具体的なら元担当が修正する。rootの直接回答はroot、Parent・workerの成果は元の作成担当が継続する。この修正だけで新担当・Advisorの起動を必須にせず、独立レビューは既存条件に従う。
- 広域・抽象的で改善点を特定しきれなければ、原依頼から別個体に再構成させる。誤り認定、不満の妥当性判定、旧担当の同意を条件にしない。同じ個体のモデル・effort変更は交代に含めず、旧作成者を作成・妥当性判定へ戻さない。
  - 委任モードではrootが別Parentを確保する。元Parentは別Parentを起動せず、引継ぎ後の並行作成を行わない。
  - Parent兼務モードでは範囲を切り出せて別workerが再作成を担える場合にそのworkerへ渡す。案件全体やroot自身の判断の作り直しが必要なら、`common/root-parent.md` に従って新しいチャットへの引継ぎを用意する。
- 再作成には原依頼・対象回答・指摘原文・確認済みの根拠を渡し、旧回答の正しさを前提にしない。作成・統合・レビューの責任、所有範囲と権限、旧担当の停止・引継ぎを明確にし、起動時は製品の編成と実在するツールを照合する。独立レビューはParentが `common/planning.md` に従って手配する。AdvisorやReviewerを作成の代わりにしない。
